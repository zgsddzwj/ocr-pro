# 收粮收购平台（ocr-pro）

一套前后端分离的收粮收购系统：**农户用小程序扫身份证 → 信息自动入库 → 收粮员在 Web 平台开收购单（粮情/扣量/单价）→ 确认开票 → 打印凭证收据**。

- **小程序端**（微信原生）：扫身份证（百炼 qwen-vl 视觉大模型识别）、信息核对修改、一键提交到平台、复制到现有系统
- **Web 平台**（React + TailwindCSS）：工作台统计、农户库、收购单录入（实时联动计算）、确认开票、凭证打印/PDF
- **后端**（Python FastAPI + SQLite）：OCR、农户/收购单/统计/设置接口、单账号登录
- 部署形态：收粮点一台电脑跑后端（一个端口、一个进程），手机与电脑同 Wi-Fi 即用

## 快速开始

### 第 1 步：启动后端（首次需装依赖 + 构建前端）

```bash
cd platform/backend
python3 -m venv .venv                       # 首次
.venv/bin/pip install -r requirements.txt   # 首次（可用清华源 -i https://pypi.tuna.tsinghua.edu.cn/simple）

cd ../frontend
npm install                                 # 首次
npm run build                               # 构建平台页面到 dist/

cd ../backend
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

启动日志会打印局域网地址（如 `http://192.168.0.103:8000`）。

### 第 2 步：初始化平台

电脑浏览器打开 `http://127.0.0.1:8000` → 首次使用设置管理密码 → 进入工作台。
在「设置」里填**公司抬头**（打印在凭证顶部）和默认品名/单价。

### 第 3 步：配置小程序

微信开发者工具导入项目根目录（AppID 已配置）→「详情 → 本地设置」勾选**不校验合法域名**。
小程序首页 → 设置 → 识别服务地址填后端局域网地址（默认已填 `http://192.168.0.103:8000`，IP 变了在这里改）→ 测试连接 ✓。

### 日常使用流程

1. **卖粮人到点** → 小程序「拍照识别身份证」→ 核对姓名/身份证号/住址 → **「提交到平台」**（同一身份证重复提交自动更新，不会重复建档）
2. **收粮员开单** → 平台「开新单」→ 搜名字选中农户（或现场手填）→ 录毛重/皮重/扣量/单价 → 净重、计价净重、价款实时算出 → 保存
3. **确认开票** → 单据详情核对 → 「确认开票」锁定（锁后不可改，防误触）
4. **打印收据** → 「打印收据 / 存 PDF」→ A5 横向凭证版式，浏览器打印即出纸质或 PDF
5. 工作台随时看今日/本月车数、吨数、结算额；农户库可搜索/编辑

## 识别准确率（模型为主，逻辑为辅）

照片歪着、拍横、拍小、拍暗都能识别，靠的是这几道关口（**没有 OpenCV、不做几何检测**——实测在杂乱背景下不可靠，方向与内容判断全部交给视觉大模型）：

1. **图片准备**（`services/preprocess.py`，纯 Pillow）：EXIF 方向校正 + 长边超限等比缩小，仅此而已；
2. **提示词**：要求"先在脑中把证件摆正再识别"，号码逐位辨认，禁止猜测编造，输出逐字段置信度；
3. **号码三重保险**（`services/idcard.py`）：国标校验位自检 → 不通过时按常见混淆表（O/0、I/1、B/8、S/5、Z/2…）**确定性纠正** → 再用号码前两位做**省籍交叉校验**；
4. **二次复读**：号码校验不过或姓名缺失时，带具体线索整卡重读；
5. **住址多角度投票**：住址对拍摄角度最敏感——0° 与 90° 各读一次，一致直接采信；不一致加读 180°、270° 取多数；仍不一致则保留结果并**明确提示人工核对**，绝不静默写入可疑数据。

**实测**（13 张样张：含倾斜 12°/-18°、透视、模糊、暗光、低分辨率、证件仅占 25%、拍屏幕摩尔纹、手持拍横的真实照片）：

| 字段 | 准确率 |
| --- | --- |
| 姓名 | 12/13 |
| 身份证号（含校验位自检与纠正） | **13/13** |
| 住址（多角度投票后） | 10/13 |
| 三项全对 | 10/13 |

> 未通过的 3 张都是刻意压到极限的样张（亮度 21%、JPEG 45、证件只占 25%），系统会主动给出"住址多次读取结果不一致，请人工核对"的提示——宁可让用户改一下，也不静默写错。

**自测工具**（在 `platform/backend` 下运行）：

```bash
.venv/bin/python tools/make_fixtures.py   # 生成 13 张困难样张到 testdata/fixtures
.venv/bin/python tools/bench_api.py       # 走真实接口跑全部样张，输出准确率表
.venv/bin/python tools/probe_models.py    # 在困难样张上对比不同 qwen-vl 模型
```

## 配置（platform/backend/.env）

```ini
BAILIAN_API_KEY=sk-xxx        # 百炼 API-KEY：https://bailian.console.aliyun.com/?apiKey=1
BAILIAN_MODEL=qwen-vl-plus    # 可换 qwen3-vl-plus / qwen-vl-max
HOST=0.0.0.0
PORT=8000
```

> **密钥安全**：`.env` 含真实密钥，不要外传整个目录；疑似泄露去百炼控制台删除重建。登录密码（PBKDF2 存储）和签名密钥（`data/secret.key`）都在服务端本机。

## 单据口径

- 编号：`YYYYMMDD + 3 位当日流水`（如 20261003001）
- 净重 = 毛重 − 皮重；扣量总重 = 场地 + 水分 + 杂质 + 生霉扣量；计价净重 = 净重 − 扣量总重
- 粮食价款 = 计价净重 × 公斤价；市斤价 = 公斤价 ÷ 2；结算价款 = 粮食价款 − 卸车费
- 金额 Decimal + ROUND_HALF_UP，大写自动生成（如 6914.80 → 陆仟玖佰壹拾肆圆捌角）
- 状态流转：草稿（可改可删）→ 已确认（锁定，可打印）→ 可作废（留档不参与统计）
- 统计口径：不含作废单

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 小程序显示服务未连接 | 后端没启动或地址/IP 不对；真机需与电脑同一 Wi-Fi 并用局域网 IP |
| 平台打不开 | 确认先执行过 `npm run build`，再重启 uvicorn |
| 「百炼 API Key 无效」 | 检查 .env 的 BAILIAN_API_KEY |
| 忘记管理密码 | 删除 `platform/backend/data/app.db` 会清空全部数据；或联系开发者重置 |
| 识别个别字段不准 | 云端识别可手动修改；反光/倾斜重拍通常更好 |
